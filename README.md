# FT812 Viewer

Плагин для Wild Commander (ZX Evolution / TS-Conf), показывающий изображения
и видео через графический чип FT812 (EVE) платы. Версия 1.0.0.

Форк [alex/ftview](https://git.alexkorochinskiy.ru/alex/ftview) (Alex
Korochinskiy; версия без `.XM`/`.XMZ`, для работы рядом с XMPLAY) для Karabas
Go / Mini G. Сюда перенесён AVI-плеер из FTView
[Wild Commander Improved v1.11i](https://github.com/andrewinsidelazarev/Wild-Commander-Improved)
(Andrew Lazarev, MIT): покадровое воспроизведение, перемотка, полоса и время.
Плагин работает со штатным Wild Commander 1.11: всё, что WC Improved брал из
внутренностей WC, здесь сделано своими силами (чтение файла с SD-карты) или
через публичный API WC. Добавлены: выбор видеорежима FT812, звук на ESP32
(ZiFi32), выход из штатного воспроизведения по Esc.

> ⚠️ **Это переработанная версия.** Стандартный (оригинальный) `ftview`
> дополнительно сам регистрируется на расширения `.XM` и `.XMZ` и
> проигрывает их через ESP32-сопроцессор. Из этой версии поддержка `.XM` и
> `.XMZ` убрана: воспроизведение модулей вынесено в отдельный плагин
> [xmplay](https://git.alexkorochinskiy.ru/alex/xmplayer.git), а у Wild
> Commander таблица "расширение → плагин" статическая и зашивается в
> заголовок при сборке — если поставить `xmplay` вместе со стандартным
> (не переработанным) `ftview`, оба будут претендовать на одни и те же
> расширения и конфликтовать. Ставить эту версию `ftview` вместе с `xmplay`,
> не стандартную.

## Требования

- ZX Evolution / TS-Conf с графическим чипом FT812 (EVE)
- Wild Commander

## Возможности

- `.JPG`, `.PNG` — просмотр изображений
- `.DLS` — воспроизведение "сырого" display list FT812 (уже скомпилированная
  команда отрисовки, без разбора формата)
- `.DXP` — свой формат растрового изображения (заголовок с сигнатурой,
  типом и размерами + данные)
- `.AVI` — видео через встроенный видеодекодер FT812: MJPEG — покадрово, с
  перемоткой, полосой и временем. Звук PCM 8 бит идёт на General Sound, а
  PCM 16 бит, IMA ADPCM, A-law, µ-law — на ESP32 (ZiFi32, прошивка со
  звуковым плеером); без GS PCM 8 бит тоже идёт на ESP32, без обоих — на
  звук FT812. Ролик, который так не пройдёт (другой звук, дробная частота
  кадров, кадр больше ~229 000 точек), играет штатный `CMD_PLAYVIDEO` без
  перемотки. Как подготовить ролик — [Подготовка видео](#подготовка-видео)

## Управление

`.JPG`/`.PNG`/`.DLS`/`.DXP`:

| Клавиша | Действие         |
|---------|-------------------|
| PgDn    | Следующий файл    |
| PgUp    | Предыдущий файл   |
| Esc     | Выйти             |

`.AVI` (покадровый режим):

| Клавиша     | Действие                    |
|-------------|-----------------------------|
| Space       | Пауза / воспроизведение     |
| ← / →       | Перемотка                   |
| Home        | С начала                    |
| Esc         | Выйти                       |

Перемотка — по индексу `idx1` (или чанку FTVIEWI1 из FTViewConvert). Файл
плагин читает с SD-карты сам (SD1 или SD2, FAT32, до 30 фрагментов), через
публичный API Wild Commander находит только начало файла — штатный WC 1.11
не меняется. Список роликов (Enter) из WC Improved не перенесён: он читает
каталог через внутренности WC.

## Установка

Скопировать `FTVIEW.WMF` ([релизы](https://github.com/andykarpov/ftview-wmf/releases))
в каталог `WC` и вписать в секцию `[PLUGINS]` файла `wc.ini`. Имя файла
можно сменить (в karabas-go он лежит как `FTVIEW32.WMF`, рядом с `FTVIEW.WMF`
Корочинского) — WC берёт его из строки `wc.ini`. Плагин сам регистрируется на
`.JPG`, `.PNG`, `.DLS`, `.DXP` и `.AVI`: в `wc.ini` должен стоять только один
просмотрщик FT812, иначе расширения достанутся первому.

Плагину нужны 11 страниц пула WC (из примерно 63): три банка кода
(изображения и разбор AVI, видеоплеер, чтение SD и ESP32) и 8 страниц
буфера. Если плагин не загружается — убрать из `wc.ini` лишние плагины.

Звук ESP32 нужна прошивка ZiFi32 со звуковым плеером (команды `0x90..0x99`,
у Karabas — `firmware/esp32-s3` репозитория karabas-go); без неё звук
PCM 8 бит идёт на GS или FT812, а остальное — штатным `CMD_PLAYVIDEO`.

### Видеорежим

Режим FT812 задаётся в строке плагина в `wc.ini` номером из таблицы
`ft_modes` SDK, например `FTVIEW.WMF -mode=7`. Без опции — режим 3.

| `-mode` | Режим                        | Частота FT812 |
|---------|------------------------------|---------------|
| 0       | 640×480@57                   | 48 МГц (пиксели 24) |
| 1       | 640×480@74                   | 64 МГц (пиксели 32) |
| 2       | 640×480@76                   | 64 МГц (пиксели 32) |
| 3       | 800×600@60 (по умолчанию)    | 40 МГц        |
| 5       | 800×600@69                   | 48 МГц        |
| 6       | 800×600@85                   | 56 МГц        |
| 7       | 1024×768@59 (исходный плагин) | 64 МГц       |
| 10      | 1280×1024@60, 640 точек по ширине | 56 МГц   |
| 13      | 800×748@48.7 (синхронно с ZX-Evo) | 40 МГц   |
| 14      | 1024×938@48.7 (синхронно с ZX-Evo) | 64 МГц  |

Режимы 4, 8, 9, 11, 12 (72 и 80 МГц) HDMI-тракт ядра не принимает, их нет.
FT812 тактируется от 8 МГц платы с умножением; чем выше частота, тем
быстрее декодирует видео, но выше штатных 60 МГц чип работает за пределами
паспорта. В режиме 10 точки вдвое шире: видео вписывается с учётом этого,
изображения показываются как есть.

## Подготовка видео

Обычное видео (MP4, MKV, WebM, ...) плеер не играет: FT812 декодирует только
MJPEG, а покадровый режим требует ещё и определённого заголовка AVI. Ролик
перекодируется на ПК конвертером `ftconv` из этого репозитория (или
FTViewConvert, см. ниже) и копируется на SD-карту.

### Требования плеера

| | Покадрово (полоса, пауза, перемотка) | Иначе |
|---|---|---|
| Контейнер | AVI (RIFF), видео — первый поток, звук — второй, других нет | — |
| Видео | MJPEG baseline (не progressive); проверено 4:2:0 со сторонами, кратными 16 (неполный блок на краю декодер FT812 пишет в соседний кадр) | другой кодек не играет совсем |
| Частота кадров | со звуком — целая (`dwScale` = 1), например 24 или 25; 23,976 и 29,97 — нет (без звука можно) | `CMD_PLAYVIDEO` |
| Кадр | до 196 608 точек (512×384) — работает всё; до 212 992 — нет звука на FT812 (только GS / ESP32); до 229 375 — ещё и без перемотки | `CMD_PLAYVIDEO` |
| Поток | на плате проверено до ~3,3 Мбит/с (512×288, 24 кадра/с); `ftconv` берёт 2 Мбит/с | — |
| Звук на GS | PCM 8 бит без знака, моно, до 37 500 Гц (рекомендуется 32 000) | — |
| Звук на ESP32 | плеер принимает IMA ADPCM, PCM 8 / 16 бит, A-law, µ-law, моно или стерео, до 65 535 байт/с; на плате без отставания проверен IMA ADPCM 32 кГц моно (16 КБ/с), PCM 8 бит 32 кГц через ESP32 шёл на 80 % скорости | MP3, AAC и прочее — `CMD_PLAYVIDEO` |
| Перемотка | `idx1` в конце файла (его пишет любой мультиплексор AVI); чанк FTVIEWI1 перед ним ускоряет первую перемотку | без `idx1` — без перемотки |
| Размер | до 1 ГБ: дальше ffmpeg пишет OpenDML, а заголовок и `idx1` описывают только первый гигабайт — плеер кончит фильм там (при 2 Мбит/с это ~55 минут; длинное — по частям) | — |

Звук PCM 8 бит идёт на GS, без GS — на ESP32, без обоих — на звуковой блок
FT812 (он одноканальный). IMA ADPCM требует ESP32 с прошивкой звукового
плеера ZiFi32; без неё такой ролик играет `CMD_PLAYVIDEO`. Экран FT812 —
режим `-mode` (по умолчанию 800×600): кадр растягивается на весь экран с
сохранением пропорций, так что 512×288 и 512×384 — разумный предел, больше
не нужно.

### ftconv

`ftconv` — программа командной строки: подбирает размер кадра по пропорциям
исходника (16:9 — 512×288, 4:3 — 512×384, стороны кратны 16), 24 кадра/с,
MJPEG ~2 Мбит/с, звук с нормализацией громкости, проверяет результат так же,
как плеер, и для звука PCM 8 бит встраивает таблицу перемотки FTVIEWI1
(у роликов для ESP32 перемотка — по `idx1`). Ролик больше 1 ГБ он не
делает, а предлагает разбить.
Рецепт видео, нормализация и таблица взяты из режима VDAC2 FTViewConvert
(Andrew Lazarev, MIT); добавлены звук IMA ADPCM для ESP32 и проверка файла.
Перекодирование делает [FFmpeg](https://ffmpeg.org/), его нужно поставить
отдельно (в программу он не вшит):

| ОС | FFmpeg | ftconv |
|---|---|---|
| Windows 10 / 11 x64 | `winget install Gyan.FFmpeg` (или архив с [gyan.dev](https://www.gyan.dev/ffmpeg/builds/): `ffmpeg.exe` и `ffprobe.exe` можно положить рядом с `ftconv.exe`) | `ftconv-windows-x64.zip` |
| macOS (Apple Silicon) | `brew install ffmpeg` | `ftconv-macos-arm64.tar.gz` |
| Linux x64 | `sudo apt install ffmpeg` (или пакет своего дистрибутива) | `ftconv-linux-x64.tar.gz` |
| любая с Python 3.8+ | как выше | `python3 tools/ftconv.py` (только стандартная библиотека) |

Сборки — на странице [релизов](https://github.com/andykarpov/ftview-wmf/releases).
Они не подписаны: Windows SmartScreen — «Подробнее» → «Выполнить в любом
случае»; macOS — `xattr -d com.apple.quarantine ftconv` (или правый клик →
«Открыть»). На Intel Mac — `tools/ftconv.py`.

```
ftconv film.mkv                       # film.avi рядом: PCM 8 бит 32 кГц (GS)
ftconv --audio esp film.mkv           # IMA ADPCM 32 кГц моно (ESP32)
ftconv --length 3000 film.mkv -o part1.avi                 # первые 50 минут
ftconv --start 3000 --length 3000 film.mkv -o part2.avi    # следующие 50
ftconv --fps 25 --crop43 -o OUT/ *.mp4    # несколько файлов в папку OUT
ftconv --check film.avi other.avi     # как плеер возьмёт готовый AVI
```

| Ключ | Что делает |
|---|---|
| `-o FILE` или `-o DIR` | имя результата или папка (по умолчанию `<имя>.avi` рядом с исходником) |
| `--audio gs` | PCM 8 бит без знака моно — GS, без GS — ESP32 или FT812 (по умолчанию) |
| `--audio esp` | IMA ADPCM — только ESP32 (вдвое меньше потока, 16 бит в декодере) |
| `--audio none` | без звука |
| `--rate N` | частота звука (по умолчанию 32000; для `gs` до 37500) |
| `--stereo` | стерео (только `esp`; на плате не проверено) |
| `--fps N` | кадров в секунду, целое (по умолчанию 24; 25 — для PAL-исходников) |
| `--bitrate N` | поток видео, кбит/с (по умолчанию 2000) |
| `--start S`, `--length S` | взять часть исходника: с секунды S, длиной S секунд |
| `-f` | перезаписать существующий результат (исходник не перезаписывается никогда) |
| `--crop43` | обрезать боковые стороны широкого кадра до 4:3 (весь экран без полос) |
| `--no-normalize` | не менять громкость |
| `--ffmpeg DIR` | где лежат `ffmpeg` / `ffprobe` (ещё `$FTCONV_FFMPEG`, папка программы, `PATH`) |
| `--check` | ничего не перекодировать: показать, как плеер возьмёт эти AVI |

В Windows файл можно перетащить на `ftconv.exe` мышью: результат
появится рядом с исходником, окно ждёт Enter (из cmd / PowerShell — не ждёт).

### FTViewConvert

[FTViewConvert](https://github.com/andrewinsidelazarev/Wild-Commander-Improved)
(Windows x64, оконный, FFmpeg внутри) из WC Improved тоже подходит: в
режиме **VDAC2** он делает тот же файл, что `ftconv --audio gs` (MJPEG
24 кадра/с, PCM 8 бит 32 кГц, таблица FTVIEWI1). Режим VDAC4 — для
другого железа (MP3, ядро Tang Nano 20K): такой звук этот плеер не играет.

### FFmpeg вручную

Без конвертера — одна команда (размер подобрать самому: стороны кратны 16;
без нормализации громкости и таблицы FTVIEWI1, перемотка — по `idx1`):

```
ffmpeg -i film.mkv -map 0:v:0 -map 0:a:0 -sn -dn \
  -vf "fps=24,scale=512:288:flags=lanczos,setsar=1,format=yuvj420p" -fps_mode cfr \
  -c:v mjpeg -huffman default -b:v 2000k -maxrate 2600k -bufsize 2000k \
  -c:a pcm_u8 -ar 32000 -ac 1 film.avi
```

Для ESP32 вместо `-c:a pcm_u8` — `-c:a adpcm_ima_wav`. Старым FFmpeg (до 5.1)
вместо `-fps_mode cfr` — `-vsync cfr`.

## Сборка

Linux, SDCC 4.3 или новее (`$SDCC_HOME`, по умолчанию `~/.local/opt/sdcc-4.4.0`), Python 3:

```
make            # FTVIEW.WMF
make venv       # .venv с intelhex, z80, Pillow — для тестов
make test        # и tools/ftconv.py (test/test_ftconv.py, нужен ffmpeg)
```

Библиотеки SDK (`vendor/`, из `pentevo/sdk/ft812sdk/lib` репозитория
zx-evo) собраны старым SDCC и принимают аргументы через стек (ABI 0).
C-код и стандартная библиотека нового SDCC — ABI 1, поэтому `tools/build.py`
не включает `--sdcccall 0` глобально (ломаются `memcmp` и 32-битное умножение),
а дописывает `__sdcccall(0)` к прототипам SDK в копиях заголовков
(`build/abi`). `__naked`-функции `src/wc_api.c` помечены `__sdcccall(0)` явно.
Плагин занимает 11 страниц пула WC (из примерно 63): три банка кода
(изображения, видеоплеер, чтение SD) и 8 страниц буфера.

## Статус

Проверено на Karabas Mini G под штатным WC 1.11 rc6: JPG/PNG, DLS,
навигация, AVI покадрово со звуком PCM 8 бит на GS и IMA ADPCM на ESP32,
перемотка, пауза, Esc, штатное воспроизведение (`CMD_PLAYVIDEO`) в режиме
по умолчанию. Karabas Go / Mini и ZX Evolution на плате не проверялись.

Не сделано: список роликов каталога (Enter) из WC Improved — он читает
каталог через внутренности WC; MP3 / AAC внутри AVI через ESP32 (движку
ESP нужно 48–64 КБ потока вперёд, см. `docs/PLAN.md`); кадры больше
~229 000 точек (640×360 уже не входит) и дробная частота кадров (23,976)
в покадровом режиме: такие ролики играет штатный `CMD_PLAYVIDEO`.

`ftconv` проверен на ПК (`test/test_ftconv.py`: размеры кадра, условия
плеера, таблица FTVIEWI1 по idx1; сборки — смоук-тест в CI на трёх ОС); его
ролики на плате ещё не проигрывались.
