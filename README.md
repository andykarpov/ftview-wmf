# FT812 Viewer

Плагин для Wild Commander (ZX Evolution / TS-Conf), показывающий изображения
и видео через графический чип FT812 (EVE) платы. Версия 1.0.0.

Форк [alex/ftview](https://git.alexkorochinskiy.ru/alex/ftview) (Alex
Korochinskiy; версия без `.XM`/`.XMZ`, для работы рядом с XMPLAY) для Karabas
Go / Mini G. Сюда перенесён AVI-плеер из FTView
[Wild Commander Improved v1.11i](https://github.com/andrewinsidelazarev/Wild-Commander-Improved)
(Andrew Lazarev, MIT): покадровое воспроизведение, перемотка, полоса и время.
Плагин работает со штатным Wild Commander 1.11: всё, что WC Improved брал из
внутренностей WC, здесь сделано своими силами (чтение файла с SD-карты) или
через публичный API WC. Добавлены: выбор видеорежима FT812, звук на ESP32
(ZiFi32), выход из штатного воспроизведения по Esc.

> ⚠️ **Это переработанная версия.** Стандартный (оригинальный) `ftview`
> дополнительно сам регистрируется на расширения `.XM` и `.XMZ` и
> проигрывает их через ESP32-сопроцессор. Из этой версии поддержка `.XM` и
> `.XMZ` убрана: воспроизведение модулей вынесено в отдельный плагин
> [xmplay](https://git.alexkorochinskiy.ru/alex/xmplayer.git), а у Wild
> Commander таблица "расширение → плагин" статическая и зашивается в
> заголовок при сборке — если поставить `xmplay` вместе со стандартным
> (не переработанным) `ftview`, оба будут претендовать на одни и те же
> расширения и конфликтовать. Ставить эту версию `ftview` вместе с `xmplay`,
> не стандартную.

## Требования

- ZX Evolution / TS-Conf с графическим чипом FT812 (EVE)
- Wild Commander

## Возможности

- `.JPG`, `.PNG` — просмотр изображений
- `.DLS` — воспроизведение "сырого" display list FT812 (уже скомпилированная
  команда отрисовки, без разбора формата)
- `.DXP` — свой формат растрового изображения (заголовок с сигнатурой,
  типом и размерами + данные)
- `.AVI` — видео через встроенный видеодекодер FT812: MJPEG — покадрово, с
  перемоткой, полосой и временем. Звук PCM 8 бит идёт на General Sound, а
  PCM 16 бит, IMA ADPCM, A-law, µ-law — на ESP32 (ZiFi32, прошивка со
  звуковым плеером); без GS PCM 8 бит тоже идёт на ESP32, без обоих — на
  звук FT812. Ролик, который так не пройдёт (другой звук, дробная частота
  кадров, кадр больше ~229 000 точек), играет штатный `CMD_PLAYVIDEO` без
  перемотки

## Управление

`.JPG`/`.PNG`/`.DLS`/`.DXP`:

| Клавиша | Действие         |
|---------|-------------------|
| PgDn    | Следующий файл    |
| PgUp    | Предыдущий файл   |
| Esc     | Выйти             |

`.AVI` (покадровый режим):

| Клавиша     | Действие                    |
|-------------|-----------------------------|
| Space       | Пауза / воспроизведение     |
| ← / →       | Перемотка                   |
| Home        | С начала                    |
| Esc         | Выйти                       |

Перемотка — по индексу `idx1` (или чанку FTVIEWI1 из FTViewConvert). Файл
плагин читает с SD-карты сам (SD1 или SD2, FAT32, до 30 фрагментов), через
публичный API Wild Commander находит только начало файла — штатный WC 1.11
не меняется. Список роликов (Enter) из WC Improved не перенесён: он читает
каталог через внутренности WC.

## Установка

Скопировать `FTVIEW.WMF` ([релизы](https://github.com/andykarpov/ftview-wmf/releases))
в каталог `WC` и вписать в секцию `[PLUGINS]` файла `wc.ini`. Имя файла
можно сменить (в karabas-go он лежит как `FTVIEW32.WMF`, рядом с `FTVIEW.WMF`
Корочинского) — WC берёт его из строки `wc.ini`. Плагин сам регистрируется на
`.JPG`, `.PNG`, `.DLS`, `.DXP` и `.AVI`: в `wc.ini` должен стоять только один
просмотрщик FT812, иначе расширения достанутся первому.

Плагину нужны 11 страниц пула WC (из примерно 63): три банка кода
(изображения и разбор AVI, видеоплеер, чтение SD и ESP32) и 8 страниц
буфера. Если плагин не загружается — убрать из `wc.ini` лишние плагины.

Звук ESP32 нужна прошивка ZiFi32 со звуковым плеером (команды `0x90..0x99`,
у Karabas — `firmware/esp32-s3` репозитория karabas-go); без неё звук
PCM 8 бит идёт на GS или FT812, а остальное — штатным `CMD_PLAYVIDEO`.

### Видеорежим

Режим FT812 задаётся в строке плагина в `wc.ini` номером из таблицы
`ft_modes` SDK, например `FTVIEW.WMF -mode=7`. Без опции — режим 3.

| `-mode` | Режим                        | Частота FT812 |
|---------|------------------------------|---------------|
| 0       | 640×480@57                   | 48 МГц (пиксели 24) |
| 1       | 640×480@74                   | 64 МГц (пиксели 32) |
| 2       | 640×480@76                   | 64 МГц (пиксели 32) |
| 3       | 800×600@60 (по умолчанию)    | 40 МГц        |
| 5       | 800×600@69                   | 48 МГц        |
| 6       | 800×600@85                   | 56 МГц        |
| 7       | 1024×768@59 (исходный плагин) | 64 МГц       |
| 10      | 1280×1024@60, 640 точек по ширине | 56 МГц   |
| 13      | 800×748@48.7 (синхронно с ZX-Evo) | 40 МГц   |
| 14      | 1024×938@48.7 (синхронно с ZX-Evo) | 64 МГц  |

Режимы 4, 8, 9, 11, 12 (72 и 80 МГц) HDMI-тракт ядра не принимает, их нет.
FT812 тактируется от 8 МГц платы с умножением; чем выше частота, тем
быстрее декодирует видео, но выше штатных 60 МГц чип работает за пределами
паспорта. В режиме 10 точки вдвое шире: видео вписывается с учётом этого,
изображения показываются как есть.

## Сборка

Linux, SDCC 4.3 или новее (`$SDCC_HOME`, по умолчанию `~/.local/opt/sdcc-4.4.0`), Python 3:

```
make            # FTVIEW.WMF
make venv       # .venv с intelhex, z80, Pillow — для тестов
make test
```

Библиотеки SDK (`vendor/`, из `pentevo/sdk/ft812sdk/lib` репозитория
zx-evo) собраны старым SDCC и принимают аргументы через стек (ABI 0).
C-код и стандартная библиотека нового SDCC — ABI 1, поэтому `tools/build.py`
не включает `--sdcccall 0` глобально (ломаются `memcmp` и 32-битное умножение),
а дописывает `__sdcccall(0)` к прототипам SDK в копиях заголовков
(`build/abi`). `__naked`-функции `src/wc_api.c` помечены `__sdcccall(0)` явно.
Плагин занимает 11 страниц пула WC (из примерно 63): три банка кода
(изображения, видеоплеер, чтение SD) и 8 страниц буфера.

## Статус

Проверено на Karabas Mini G под штатным WC 1.11 rc6: JPG/PNG, DLS,
навигация, AVI покадрово со звуком PCM 8 бит на GS и IMA ADPCM на ESP32,
перемотка, пауза, Esc, штатное воспроизведение (`CMD_PLAYVIDEO`) в режиме
по умолчанию. Karabas Go / Mini и ZX Evolution на плате не проверялись.

Не сделано: список роликов каталога (Enter) из WC Improved — он читает
каталог через внутренности WC; MP3 / AAC внутри AVI через ESP32 (движку
ESP нужно 48–64 КБ потока вперёд, см. `docs/PLAN.md`); кадры больше
~229 000 точек (640×360 уже не входит) и дробная частота кадров (23,976)
в покадровом режиме: такие ролики играет штатный `CMD_PLAYVIDEO`.
